# SgsClient 客户端架构（M0）

## 总体结构

客户端采用轻量的 C++/QML 分层。C++ 提供进程入口、应用生命周期和未来的数据/服务边界；QML 只负责桌面界面的布局、展示和轻量交互。M0 不引入网络、规则或资源管理实现。

```text
main.cpp
  -> QGuiApplication
  -> Application
       -> QQmlApplicationEngine
            -> SgsClient/Main.qml
```

## C++ 与 QML 的职责边界

C++ 负责应用初始化、错误处理以及未来的网络访问和客户端数据模型。复杂状态变化、协议解析和游戏规则不得放入 QML。QML 负责窗口、控件、布局、动画表现和把用户操作转交给 C++ 接口；当前按钮只有明确的“功能开发中”占位反馈。

## Application 生命周期

`main.cpp` 首先创建 `QGuiApplication`，随后在其作用域内创建 `Application`。`Application` 借用 Qt 应用对象并独占 `QQmlApplicationEngine`，设置名称和版本后，通过 `loadFromModule("SgsClient", "Main")` 加载由 CMake 编译进程序的 QML 模块。

若 QML 根对象未创建，初始化立即失败并返回非零退出码；异步的 `objectCreationFailed` 信号也会请求失败退出。正常关闭时，`Application` 和引擎先析构，`QGuiApplication` 后析构，从而保证 QML 对象的生命周期合法。

## 后续模块的预期职责（仅规划）

- `Network`：连接管理、收发、重连与统一协议的编解码；协议由双端架构负责人后续确定。
- `Model`：向 QML 暴露客户端可观察状态，不承载服务端权威规则。
- `Lobby`：大厅列表、匹配或房间入口的表现和交互协调。
- `Room`：房间成员、准备状态及房间内操作的客户端视图。
- `GameTable`：牌桌状态表现、动画和合法操作输入的采集。

以上名称表示职责边界，并非已经落地的目录、类型或跨端消息名称。M0 不提前创建这些模块。

## 服务端边界

Linux 服务端是游戏规则和对局状态的权威来源。客户端只负责提交用户操作、维护必要的展示状态并表现服务端结果。通信协议、消息格式、错误码和版本协商将在后续由双端统一规定，客户端不得单方面定义。

## 资源扩展方向

未来图片、音频和动画资源应在协议与产品命名确定后建立统一索引、加载和缺失回退机制。M0 只使用 Qt 控件、颜色和文字，不建立复杂资源绑定系统。
